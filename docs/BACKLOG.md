| B39 | **Shell integration** — the shell talking to the terminal on purpose: `OSC 133` prompt/command/exit-status marks, `OSC 7` cwd, `OSC 2` title written by the prompt, a notification when a long command ends (`OSC 9`/`777`, already in the core), `DECSCUSR` driven by the keymap (the terminal side also already exists) — and, with the marks in place, everything that only the shell knows: where the prompt starts, where the command ends, what the exit status was | the title is only the visible edge of it, and it is not a gap: what the tab shows today (`OSC 0/2`, else `basename(cwd)`, else `tortty`) is the right answer for what a terminal knows alone — kitty and ghostty show `~` only because their own script writes it. What is missing is the other side: the child is a wall of bytes, the cwd is guessed from `/proc`, and the terminal cannot tell a prompt from output. The marks are the substrate that turns the scrollback into zones: jump between prompts, take the output of the last command, click to move the cursor, redraw the prompt cleanly on resize, the running command in the tab label | the substrate landed 2026-11-13 (`OSC 133` marks in the core, prompt navigation on Ctrl+Shift+Up/Down) — the escapes are in place, and while the core throws `133` away nothing else in this item can exist. If `$HOME` as `~` becomes an itch earlier, the honest answer is a line in the `.zshrc`, not a reason to open this | high, and a programme rather than one commit: substrate in the core (`M-R`), then an integration layer (documented snippet first; injection through `ZDOTDIR`/`ENV`/`XDG_DATA_DIRS` only with a way to turn it off), one script per shell (zsh, bash, fish), and on the app side the consumers — prompt navigation, command-output selection, adaptive redraw, tab label state |
| B56 | **Which chrome comes from egui** — the cards and the tab bar stay hand-drawn; the form-like pieces are the candidates: the `M-V` context menu, the `F3` config editor, the command palette, the toast with buttons | measured on 2026-11-10 with the mock in `mockups/egui-chrome/`, same palette and proportions as `render.rs`: one rebuild of the whole chrome costs **0.04 ms** in release (708 triangles, `bin/bench`), so the frequency is not the obstacle — at 10 fps that is 0.4 ms/s, and the grid never pays it because the cached mesh is re-issued between rebuilds. The obstacle is geometry: with widgets the card of `tail -f /var/log/syslog` **grows** (the text wraps instead of being cut), the 18-cell column becomes a fixed 180 px off the grid, and the item spacing is the toolkit's, not a multiple of a cell — the trap of `B42`/`B43`.
